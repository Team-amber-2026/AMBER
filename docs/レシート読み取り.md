# 機能仕様：レシート読み取り（OCR）

## 概要
Reactで取得した画像をTesseract.jsでブラウザ内解析し、確認済みの支出データだけをDjango REST APIへ送信する。

## ワークフロー
1. **Frontend**: `input type="file"` またはカメラ起動で画像を取得。
2. **Frontend**: 元画像、グレースケール・コントラスト補正版、二値化版を同じTesseract.js Web Workerで認識する。店名は元画像から高解像度でヘッダーを再認識する。本文の行数や通貨候補が少ない場合は元画像中央部を高解像度で追加認識し、合計が不確かな場合は元画像下部も追加認識する。レシート上部は通常画像と色反転画像でも認識する。
3. **Frontend**: 通常5パスと条件付きの本文・合計再認識結果から、店名・購入日・合計金額を項目別に抽出する。候補の一致回数、ヘッダー領域由来か、項目の表記・位置条件を組み合わせ、単一のOCR信頼度だけで候補を決めない。OCR全文は元画像・補正版・二値化版のうち最も妥当な1パスを基礎にし、本文再認識で欠落していた商品行だけを重複除去して補う。
4. **Frontend**: ユーザーが確認・修正後、保存ボタンを押す。
5. **Backend**: 確認済みデータとOCR抽出値を支出・修正履歴としてDBに保存する。

## 利用エンドポイント
- `POST /api/expenses/`: 確認済みの支出とOCR抽出値を保存する
- `GET /api/categories/`: 選択可能なカテゴリ一覧を取得する
- `POST /api/categories/classify/`: 店名・OCR全文からカテゴリを自動分類する

## 注意点
- OCR解析時点ではDB保存しない。
- ユーザーが確認・修正して保存した後にDBへ登録する。
- OCRの読み取りミスに備えて、日付・店名・合計金額・カテゴリーは手動修正できるようにする。
- 保存時に、OCRの抽出値と修正後の支出値を修正履歴として保存する。
- レシート画像はブラウザ外へ送信・保存しない。
- 初回は日本語・英語の学習データをダウンロードするため、解析開始まで時間がかかる場合がある。
- 複数画像では同じWeb Workerを再利用する。
- 店名・購入日・合計金額の項目別信頼度が70%未満、または候補がない場合、その項目だけレシート画像との照合を促す。

## OCR精度の評価基準

Issue #53の検証方針に合わせ、改善前後を同じ評価用画像と正解データで比較する。公開Issueには個人情報を含む実レシート画像を添付しない。

- 店名、購入日、合計金額を項目別に完全一致率で測定する。
- 店名がブランド名と支店名の2行構成の場合は、`FamilyMart 五条大宮店` のように結合した値を正解データと比較する。
- 3項目すべてが正解となる割合も別に測定する。
- 文字認識の誤りと、認識後の項目抽出の誤りを分けて記録する。
- 2桁年、区切り文字、全角半角、通貨記号などの正規化ルールを評価条件に明記する。
- OCR信頼度だけで精度を判断せず、候補の一致回数と手動修正率も記録する。
- スマートフォン実機で、初回・2回目以降の処理時間とメモリ負荷を確認する。

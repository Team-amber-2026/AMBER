# 機能仕様：ユーザー認証（Session Auth）

## 概要
Django標準の認証システムを利用し、Reactフロントエンドとセッションベースで連携する。

## 技術詳細
- **Backend**: Django REST Framework（DRF）の `SessionAuthentication`
- **Frontend**: Axiosによる認証リクエスト
- **セキュリティ**: CSRFトークンのやり取りを必須とする
- **認証方式**: Cookieを利用したセッション認証

## エンドポイント案
- `GET /api/auth/csrf/`: CSRFトークン取得
- `POST /api/auth/register/`: 新規登録
- `POST /api/auth/login/`: ログイン
- `POST /api/auth/logout/`: ログアウト
- `GET /api/auth/user/`: ログイン中のユーザー情報取得

## 注意点
- ReactからDjangoへリクエストする際は、Cookieを送信する設定を行う。
- Axiosでは `withCredentials: true` を使用する。
- 本番では全APIを相対パス `/api/*` 経由で呼び、Vercel RewriteでRenderへ転送する。ブラウザはVercelホストに認証Cookieを保存する。
- 本番CookieはDomainなし・Path `/`・SameSite `Lax`・Secure `True`。`sessionid` はHttpOnly、`csrftoken` はAxiosのヘッダー設定のためJavaScriptから参照可能とする。
- Axiosは `csrftoken` を `X-CSRFToken` に設定する。ログインでCookieが更新されたら、その最新値を使用する。
- 登録成功後はログイン画面へ進む。ログイン後の認証維持とログアウトを同じブラウザセッション内で確認する。
- Django側ではCORSとCSRFの設定を行う。
- APIキーやパスワードなどの機密情報はフロントエンドに置かない。

## 新規登録時のパスワード案内（Issue #42）

- Reactの新規登録画面とDjangoの登録フォームは、入力前から「8文字以上」「よく使われるパスワードは不可」「数字のみは不可」を表示する。
- 文字種や記号の制限、英字と数字の組み合わせ条件は追加しない。確認用パスワード欄も追加しない。
- 条件違反はサーバーで検証し、パスワード・ユーザー名・メールアドレス・通信などのエラーはすべて画面上部のエラー枠にまとめて表示する。パスワード欄の下は条件案内のみとし、同じエラーを重複表示しない。上部のエラー枠は `role="alert"` で読み上げに対応する。
- `RegisterSerializer.validate_password` は `validate_password(value)` をユーザー情報なしで呼ぶため、設定内の `UserAttributeSimilarityValidator` は登録時には適用されない。今回、検証条件は変更していない。
- バリデーター設定や登録時の検証方法を変更するときは、両方の画面の案内も更新する。8文字の境界値、よく使われる値、数字のみ、英字のみ、日本語、記号のみを登録APIのテストで確認する。

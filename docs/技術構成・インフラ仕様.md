# 技術構成・インフラ仕様

## 構成

本番の通信経路は **Vercel → Render Web Service（Django API） → Neon（PostgreSQL）**。

- **Frontend**: React（Vite） -> Vercel
- **Backend**: Python（Django） -> Render Web Service
- **OCR**: Tesseract.js（WebAssembly / Web Worker） -> ユーザーのブラウザ
- **Database**: Neon の PostgreSQL（本番）。ローカル開発では `DATABASE_URL` 未設定時に SQLite を使う。
- **Storage**: OCR用の画像ストレージは使用しない。レシート画像はブラウザ外へ送信しない。

## 環境変数の管理

ローカル開発は `.env`、本番は各サービスのダッシュボードで管理する。

- `SECRET_KEY`: Djangoのシークレットキー
- `DEBUG`: 開発環境ではTrue、本番環境ではFalse
- `DATABASE_URL`: Neon の本番ブランチ・データベースへの PostgreSQL 接続文字列。`render.yaml` の `sync: false` に対応する値を Render の本番 Web Service に設定する。
- `CORS_ALLOWED_ORIGINS`: フロントエンドのURLを許可
- `CSRF_TRUSTED_ORIGINS`: CSRFを許可するフロントエンドURL

## 注意点
- `.env` はGitHubにアップロードしない。
- Tesseract.jsはReact側のWeb Workerで実行し、日本語・英語の学習データをブラウザへキャッシュする。
- 選択した画像範囲をブラウザ内で解析する。認識の詳細は [レシート読み取りの仕様](レシート読み取り.md) を参照する。
- レシート画像はDjango、Render、外部OCR API、共有ストレージへ送信しない。
- OCR用のRender Background Workerや外部API契約は不要。
- 初回から完全オフラインにする場合はWorker、WASM、学習データを自サイトから配信する。
- 本番環境では `DEBUG=False` にする。
- 本番のAPI接続先は `/api` 固定。Vercel Rewriteで `https://amber-api-usdz.onrender.com/api/:path*/` に転送し、Django APIの末尾スラッシュを保持してブラウザからの認証通信を同一オリジン化する。SPAフォールバックは `/api` を除外する。
- 転送先は `frontend/vercel.json` で管理する。変更時は再デプロイが必要。Previewも同じ転送先を利用する。
- `VITE_API_BASE_URL` は Vercel では `/api` に揃える。ローカル開発では未設定時に `http://localhost:8000/api` を使用する。
- Render側には Vercel のURLを `FRONTEND_ORIGIN` / `CORS_ALLOWED_ORIGINS` / `CSRF_TRUSTED_ORIGINS` に設定する。
- 同一オリジン通信でもDjangoが受け取るOriginはVercel URLなので、`CSRF_TRUSTED_ORIGINS` に本番・検証対象PreviewのURLを明示する。
- 本番CookieはDomainなし・Path `/`・SameSite `Lax`・Secure `True` とする。`DEBUG=False` のSecure既定値は `True`。既存のDashboard設定も合わせて更新する。
- `SECURE_PROXY_SSL_HEADER` は `X-Forwarded-Proto: https` を使用する。`ALLOWED_HOSTS` は転送先のRenderドメインを維持する。
- 公開環境のSafari・Chrome・Edge通常／プライベート確認手順はREADME「同一オリジン認証の公開環境確認」を参照する。

## 本番DBの確認

- Render の `DATABASE_URL` が、Neon Console の **Connect** で選んだ本番ブランチ・データベースを指すことを確認する。接続方法は [Neon の接続ガイド](https://neon.com/docs/connect/connect-from-any-app) を参照する。
- 本番サイトでテスト用の支出を保存し、ページを再読み込みしても支出一覧に表示されることを確認する。
- 認証とOCRも確認したら、Vercel・Render の反映コミットと結果を [Issue #30](https://github.com/Team-amber-2026/AMBER/issues/30) に記録する。DB接続の記録は「Neon本番DBへの接続確認済み」とし、接続文字列は記載しない。
